テスト表を作る 境目でまちがえる理由 よくある質問

入力チェックのテストで見るべき値は、だいたい決まっています。下限と上限のちょうど、その1つ手前と1つ先、範囲の中と外の代表値。それでも毎回手で書くと、「以上」と「より大きい」を取りちがえたり、全角数字の扱いを決めないままテストが始まったりします。このツールは条件から境界値分析（2値・3値）と同値分割のテストケースを作り、数直線で有効と無効の切れ目を見せます。すべてブラウザ内で計算しています。

境目でまちがえる理由

仕様書の「18歳以上」は、実装では age >= 18 になります。ここを age > 18 と書いてしまうと、18歳ちょうどの人だけが登録できません。17歳と30歳で試しても、どちらの実装でも同じ結果になるので、このミスは見つかりません。境界値のテストは、境目ちょうどの値を入れて初めて意味を持ちます。

もうひとつ多いのが、仕様で決めていない値です。全角の「１８」を入れたら受け付けるのか。「 18 」のように空白が付いていたら。0.05 刻みの欄に 0.051 を入れたら丸めるのか弾くのか。これは実装のバグというより、決めていないことが画面に出ているだけです。このツールはそういう値の期待結果を「要確認」として出し、テストの前に決めるべきことの一覧として使えるようにしています。

考え方の整理は テスト技法カタログ、練習問題は テスト技法ドリル にあります。日付の境界は 意地悪な日付ジェネレーター、ファイルの容量や画像サイズの境界は ダミーファイル生成ツールの境界値セット で、実際のデータを作れます。

よくある質問

境界値の「2値」と「3値」はどう違いますか？+
2値は、有効と無効が入れかわる境目をはさむ2点だけを試します（18以上なら17と18）。3値は、境界そのものと、その両どなりの3点を試します（17・18・19）。3値のほうが件数は増えますが、「18以上」を「19以上」とまちがえて実装したようなずれも見つけられます。
「以上」と「より大きい」で、テストする値は変わりますか？+
変わります。「18以上」なら18が有効、「18より大きい」なら18は無効です。境界ちょうどの値の期待結果が入れかわるので、仕様書の言葉をそのまま選んでください。実装では <= と < の取りちがえがよく起きる場所で、このツールの数直線では有効と無効の切れ目に線を引いています。
「要確認」はどういう意味ですか？+
全角数字、前後の空白、刻みより細かい小数、絵文字の文字数など、仕様書に書かれていないことが多く、有効か無効かを決めつけられない値です。テストの前に、仕様としてどう扱うかを決めておくための問いとして使ってください。
文字数のテストで、絵文字が入っているのはなぜですか？+
文字数の数え方が実装によって違うためです。JavaScript の length では絵文字1つが2と数えられ、UTF-8 のバイト数では4バイトになります。画面では20文字で通るのに、サーバーやデータベースで弾かれる、というずれがここで見つかります。
作った表をExcelで開けますか？+
開けます。「CSVをダウンロード」は Excel で文字化けしないよう UTF-8 の BOM を付けています。そのまま貼り付けたいときは、TSV を選んでコピーし、Excel のセルに貼ると列が分かれます。
入力した条件はサーバーに送られますか？+
送られません。テストケースの計算はすべてブラウザ内（あなたの端末上）で行っていて、サーバーには何も送信していません。

技法の考え方は テスト技法カタログ、組み合わせのテストは ペアワイズ生成器、入力欄を壊しにいく値は 意地悪テストデータ生成器、日付の境界は 意地悪な日付ジェネレーター をどうぞ。
