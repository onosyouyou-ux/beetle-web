# コントラスト比チェッカー（`tools/contrast/`）

- **目的**: 背景色と文字色のコントラスト比を判定し、落ちたときに「元の色みを保ったまま通る色」まで提案する静的ツール。`ui-parts`（UI部品の名前と観点）に対する、数値で決着をつける側の入口
- **レイアウト型**: Reference系（[_common.md](_common.md) 参照）＋インタラクティブ部
- **構成**: `#tool`（調べる：入力・スウォッチ・判定・プレビュー・提案）→ `#cvd`（色覚シミュレーション）→ `#about`（基準の読み方）→ `#faq`
- **主要素**: `#ct-bg`／`#ct-fg`（カラーピッカー）と `#ct-bg-hex`／`#ct-fg-hex`（16進入力。双方向に同期）・`#ct-swap`・`#ct-swatches`（`.ct-swatch` の `data-bg`/`data-fg`）・`#ct-ratio`・`#ct-judge`（5段階の合否）・`#ct-preview`・`#ct-fix`（`.ct-apply` で提案色を適用）・`#ct-cvd`

## 計算のしかた

- **コントラスト比**: WCAG 2.1 の相対輝度。sRGB を線形化（`v<=0.04045 ? v/12.92 : ((v+0.055)/1.055)^2.4`）し、`0.2126R + 0.7152G + 0.0722B` から `(L明+0.05)/(L暗+0.05)`
- **検算値**（実装を変えたらこの4つで確かめる）: 白×黒 = 21.00 ／ 白×#777777 = 4.48（落ちる）／ 白×#767676 = 4.54（通る）／ 同色 = 1.00
- **判定の段階**: 通常AA 4.5／通常AAA 7／大きい文字AA 3／大きい文字AAA 4.5／UI部品AA 3
- **通る色の提案**: HSLに変換し、**色相と彩度を固定して明度だけ**を上下に1%刻みで動かし、4.5:1 に届く最も近い色を採る。明るくする側・暗くする側の両方を試し、移動量が小さいほうを選ぶ。届かない場合は「色相か彩度も変える必要がある」と出す
- **色覚シミュレーション**: Viénot らの近似行列（1型・2型・3型の2色覚）を線形RGB上で適用。**近似であること**をFAQに明記する

- **挙動（E2Eで検証）**:
  - 初期表示はBEETLEの地色 `#f7f5f0` × 補助文字色 `#888780` で、比率 3.31（通常サイズの文字AAは不足、大きい文字AAは合格）
  - 落ちているときだけ `#ct-fix` に提案カードが2枚（文字色を変える／背景色を変える）出る。「この色にする」で入力欄に反映され、再判定される
  - 赤 `#d13b3b` × 緑 `#3ba13b` を入れると、2型のシミュレーションで両色が近づき比率が 1.17 まで落ちる（色だけで区別している配色が消える実演）
  - 不正な色コードを入れると `#ct-judge` にエラーが出る
- **手動確認観点**:
  - 提案された色が実際に読めるか（`.ct-fix-pv` のプレビューで確認する。数値が通っていても違和感がある場合は採らない）
  - 「基準は下限であって目標ではない」という但し書き（`.ct-caveat`）が残っているか。数値だけで良し悪しを断定させない
  - 色覚シミュレーションが「近似」であることが本文とFAQの両方に書かれているか
