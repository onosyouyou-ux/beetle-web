# 班分けメーカー（`tools/hanwake/`）

- **目的**: 名簿と配慮からグループ分けを作る先生向けの静的ツール。**席替えメーカーの姉妹ツール**。
  席替えのFAQに「班の形の席にはできますか？」という質問を置いていた（＝需要を想定していた）ので、そこを埋める
- **由来**: 席替えと同じ「制約を守る配置をランダムに探す」問題なので、解法・名簿UI・保存・印刷をほぼ流用できる。
  新規ツールの中でいちばん安く出せる、という理由で 2026-08-24 に着手した
- **レイアウト型**: 教育系の静的アプリ（[_common.md](_common.md) 参照）。紙面 `.app-paper` 1180px ＋ モザイクタイル背景。
  配色・トーンは `sekigae.css` に揃える（先生が職員室で使う画面）
- **主要素**: `#hw-names`（名簿）・`#hw-rules`（配慮）・`#hw-mode`（班の数／1班の人数）・`#hw-num`・
  `#hw-count`・`#hw-plan`・`#hw-sample`・`#hw-gen`／`#hw-again`・`#hw-board`（班カード）・`#hw-msg`・
  `#hw-info`・`#hw-out`（TSV）・`#hw-remember`・`#hw-copy`・`#hw-print`

## 名簿は席替えメーカーと共有する

- `js/class-roster.js` が両ツール共通の名簿モジュール。**localStorage の `beetle.rosters.v1` 1か所**に保存し、
  席替えで保存したクラスを班分けから呼び出せる（その逆も）。旧キー `beetle.sekigae.rosters.v1` からは初回に自動で引き継ぐ
- レコードは共通で、ツール固有の結果だけ別フィールドに持つ：
  `rules`/`cols`/`rows`/`seating`/`seatingAt`（席替え）と `hanwakeRules`/`grouping`/`groupingAt`（班分け）。
  **上書き保存のときは相手のフィールドを引き継ぐこと**（消すと片方のデータが飛ぶ）
- 共通モジュールが持つのは「保存・CSV取り込み・名前の読み取り・小道具」。**DOMには触らない**（idがツールごとに違うため）
- 班分けはラベル付きなので `people: [{name,label}]` と構造化した `hanwakeRules` も持つ。
  席替えはテキストの `names` しか見ないので、保存時は**両方**書く（`namesText()`）
- CSV取り込みは Shift_JIS 自動判別・引用符つきセル対応。列は押すたびに
  **「なまえ」→「ラベル」→ なし** と切り替わり、名前は複数列えらべる（姓と名が別列でも1人にまとまる）。
  **性別の列をラベルに指定すれば、そろえる項目が一発で埋まる**
- CSVは出す側も用意した：`ひな形CSV`（出席番号・なまえ・ラベルの見本）と、結果の `CSVで保存`。
  どちらも **UTF-8 BOM 付き**で書く（付けないと日本語Excelで文字化けする）

## 入力はフォーム（2026-08-24に textarea から変更）

初版はテキスト記法（`別々: 田中, 佐藤`）だったが、**名前を名簿と同じ書き方で打ち直させるのが負担**なので、
1人1行・配慮1件1行のフォームに変えた。**配慮の名前は名簿から選ぶ**ので、打ち間違いも
「名簿にありません」エラーも構造的に起きなくなった（そのぶんの検証コードも消えた）。

- **名簿の行**（`#hw-rows`）: なまえの入力＋そろえる項目のトグル＋×。`＋ 人を追加`、
  **なまえ欄で Enter → 次の人（最後なら1人増やす）**、**複数行を貼ると自動でその行数に展開**する。
  35人をExcelから貼る流れを殺さないため、`まとめて貼り付け`（textarea）も残してある
- **そろえる項目**（`#hw-labelset-input`、既定 `女, 男`）: 性別は打つより押すほうが速いのでトグルにした。
  項目を書き換えれば係や委員会にも使える。**3つまで**（1行に収まらなくなるため）
- **配慮の行**（`#hw-rules`）: 種類のselect＋人のチップ＋×。人はプルダウンから選び、選択済みは候補から消える
- 内部モデルは `people = [{id,name,label}]` と `rules = [{id,kind,ids}]`。
  **rules は人を id で持つ**（名前で持つと、改名や同姓同名で壊れる）
- 表示名は `displayNames()` が確定させる（同姓同名は2人目以降に `（2）`）

## 配慮の種類

種類は3つ。`別々` と `ちらす` は**まったく同じ制約**（選んだ人全員がちがう班）で、
先生の意図が違うだけ。結果に出すタグは `tagOf` に選んだほうの語を覚えて表示する。

| 種類 | 内部 | 強さ |
|---|---|---|
| `別々` | apart | **必ず守る** |
| `ちらす` | apart（同上） | **必ず守る** |
| `同じ` | together | **必ず守る** |
| そろえる項目（名簿側のトグル） | balance | できるだけ守る |

## 班の決め方

- **人数の割り振り**: 35人4班なら 9,9,9,8（`groupSizes()`）。端数は先頭の班から1人ずつ足す
- **アルゴリズム**: `同じ` をつないで「かたまり」にし（union-find）、かたまり単位でランダムに配ってから、
  **同じ大きさのかたまりを交換する山登り**で詰める。ランダムに置くだけでは「前回と同じ顔ぶれ」が0にならなかったため。
  交換を同じ大きさに限るのは、班の人数を崩さないため
- **スコア**（小さいほどよい）: `前回と同じ組 × 10 ＋ そろえるの偏り × 3`。
  必須条件（別々・同じ・人数）を満たす配置の中から、いちばんスコアの低いものを選ぶ
- **「同じ」で組ませた2人は、前回と同じでも重複に数えない**。数えると「避けきれませんでした」という嘘の警告が出る
- **「そろえる」の偏りは、割り切れないぶんが必ず残る**（15人を6班なら理想2.5人で、実際は2か3にしかできない）。
  `minBias()` でその下限を先に出し、**下限を超えたときだけ**警告する。ここを固定値と比べると毎回誤報になる
- **作れないときは理由を具体的に出す**（`diagnose()`）: 班の数が人数より多い／`同じ` が1班に入りきらない／
  `同じ` と `別々` の矛盾／`ちらす` が班の数を超える／名簿にない名前

## 前回と同じ班を避ける

- 結果の「この班をおぼえる」で、いま選ばれている名簿に `grouping` として書き込む
- よびだすと `#hw-prev` が出て「前回と同じ人と同じ班にしない」を選べる
- **エラーにはしない**（人数と班の数によっては原理的に避けきれない）。残った組数を `#hw-msg` に出す

## 検証済み（2026-08-24 ブラウザで実測）

- 見本（30人・6班・配慮4種）で**100回連続**して、別々・同じ・ちらす・人数・重複なし の**違反0件**
- 「おぼえる → 引き直す」を**10世代連続**で、前回と同じ組み合わせ **0件**（山登り導入前は毎回3組残っていた）
- 1回の班分けにかかる時間は約200ms
- エラー系はそれぞれ固有のメッセージになる（矛盾／ちらしきれない／同じが大きすぎ）
- フォーム化後も見本30人・6班で**60回連続**して違反0件。行の追加・削除・Enter送り・複数行貼り付け・
  トグル・CSVのラベル列取り込み・ひな形CSV・結果CSV（BOM付き）を実機で確認
- **人数より班が多いとき**は `#hw-plan` に「4人を6班には分けられません」と出す
  （初版は「6班（1班 0〜1人）」という意味のない表示になっていた）
- 席替えメーカーで保存した名簿を班分けから呼び出し、班分け側で上書き保存しても
  席替えの `seating`・`rules` が残ることを確認

- **手動確認観点**:
  - 「名簿はサーバーに送りません」の表示が消えていないか（このツールの前提そのもの）
  - 「消す」の確認ダイアログは `window.confirm`。**自動テストからは押さない**（ブラウザのモーダルで操作が止まる）
  - 印刷プレビューで班カードが途中で切れないか（`break-inside: avoid` を入れてある）
