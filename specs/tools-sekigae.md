# 席替えメーカー（`tools/sekigae/`）

- **目的**: 名簿と配慮から座席表を作る先生向けの静的ツール。学級通信メーカーに続く**先生向け2本目**。
  名簿という個人情報を扱うため、**サーバーに一切送らないこと自体が機能**であり、それを画面上でも明示する（`.sk-privacy`）。
  2026-08-24に名簿の保存・CSV取り込み・前回の席の回避を追加したため、**「保存しない」ではなく「サーバーに送らない／保存はこの端末のブラウザの中だけ」**が正しい表現。
  `.sk-privacy`・使い方・FAQ・ランディングのPRIVACY節とFAQ（JSON-LD含む）は、この言い回しで揃えること
- **レイアウト型**: 教育系の静的アプリ（[_common.md](_common.md) 参照）。紙面 `.app-paper` 1180px ＋ 余白はモザイクタイル `bg-mosaic.png`。
  ヘッダーは共通パーシャル、フッターはアプリ共通フッター（**ヒーローズバナーは付けない**＝テスト検証用ツールのみ）。
  SEOは `landing.html` に集約し、アプリ本体の canonical もランディングへ向ける。既存の使い方・配慮・FAQは利用中の補助情報として残す
- ヒーローに教室の画像と「リファレンス」リンクを表示し、`landing.html` へ移動する
- **トーン**: 子ども向けアプリ（さんすう・えいご）より落ち着いた配色。先生が職員室で使う画面という想定
- **主要素**: `#sk-names`（名簿）・`#sk-rules`（配慮）・`#sk-cols`／`#sk-rows`（2〜10。既定6×5）・`#sk-count`・`#sk-seats`・`#sk-sample`（見本）・`#sk-gen`／`#sk-again`・`#sk-board`（座席表）・`#sk-msg`・`#sk-info`・`#sk-out`（TSV）・`#sk-copy`・`#sk-print`

## 入力の読み方

- **名簿**: 1行1人。`1 田中` のような出席番号つきでも名前だけを取り出す（`cleanName()`）。
  同姓同名は区別できないため、2人目以降に `（2）` を付けて別人として扱う
- **配慮**: `種類: 名前` の形。種類は `離す`／`前列`／`後列`／`固定` の4つ（それぞれ表記ゆれを許容）。
  `固定` だけ `名前 = 2れつ 3ばん` の形で、右側の数字2つを「列・番」として読む。
  配慮欄では名簿のフルネームでなくても、**部分一致で1人に絞れれば**その人として扱う（2人以上該当したらエラー）

## 名簿の流し込み（2026-08-24追加）

名前を毎回打ち直さずに済ませるための入口が3つある。いずれも**ネットワークには一切出さない**。

- **名簿まわりは `js/class-roster.js` に共通化**（2026-08-24。班分けメーカーと共有）。
  保存・CSV取り込み・名前の読み取りはこのモジュールが持ち、DOMとの配線だけ各ツールに置く。
  **保存先は `beetle.rosters.v1` の1か所**で、席替えで保存したクラスを班分けから呼び出せる（逆も）。
  旧キー `beetle.sekigae.rosters.v1` からは初回に自動で引き継ぐ。
  レコードは共通なので、**上書き保存では相手のフィールド（`hanwakeRules`・`grouping`）を引き継ぐこと**
- **名簿の保存・よびだし**（`#sk-roster-list` / `#sk-roster-load` / `#sk-roster-save` / `#sk-roster-del`）:
  `[{id,label,names,rules,cols,rows,seating,seatingAt,hanwakeRules,grouping,groupingAt,savedAt}]` で持つ。
  クラスを何本でも保存できる。保存名は `#sk-save-row` のインライン入力で付ける（`prompt()` は使わない）。
  localStorage が使えない環境（プライベートモード等）では読み書きとも `try/catch` で握りつぶし、「保存できませんでした」と出して通常動作は続ける
- **CSV / Excel 取り込み**（`#sk-csv`）: `FileReader` で ArrayBuffer として読み、UTF-8で復号して `�` が混ざれば **Shift_JIS で読み直す**
  （学校の名簿CSVはShift_JISが多い）。区切りは1行目のタブ数とカンマ数で判定。引用符つきセルに耐えるパーサを自前で持つ。
  列は `#sk-csv-pick` で**複数選択できる**（姓と名が別列のとき両方えらぶと半角スペースで連結）。漢字かなが多い列を初期選択にする
- **前回の席を避ける**（`#sk-prev`）: 座席表で「この席をおぼえる」（`#sk-remember`）を押すと、いま選ばれている名簿に `seating` として書き込む。
  よびだすと `#sk-prev` が現れ、「前回と同じ席にしない」「前回と同じ隣にしない」を選べる

## 席の決め方

- **座標**: `grid[r][c]`、`r` は前から（0が最前列）、`c` は黒板から見て左から
- **前列** = 前から2列目まで、**後列** = 後ろから2列目まで（`FRONT_DEPTH`／`BACK_DEPTH`）
- **離す** = 前後左右の隣にしない。**斜めは隣として数えない**（FAQに明記）
- **アルゴリズム**: ランダム再試行（最大4000回）。固定席を先に置き、次に**席の候補が狭い順**（前列・後列指定 → その他）に、
  その時点で「離す」に触れない空席へランダムに置く。全員置けたらその配置を返す
- **前回の席の回避は「守れなければ自動でゆるめる」**（`prevAttempts()`）。きつい順に
  「席も隣も避ける」→「隣だけ避ける」→「席だけ避ける」→「前回条件なし」を試し、通ったところで採用する。
  ゆるめたときは `#sk-msg` にその旨を出す（エラーにはしない）。2×2に4人のように**原理的に隣を避けられない**配置があるため、
  ここをエラーにすると使えなくなる
- **作れないときは理由を具体的に出す**（`diagnose()`）。席不足・固定席の重複／範囲外・前列や後列の定員超過・前後列の矛盾は
  探索の前に検出して数字つきで説明する。それ以外は探索失敗として「条件を1つ減らすか席を増やす」よう促す

- **挙動（E2Eで検証）**:
  - 「見本を入れる」で30人＋4つの配慮が入り、席の数も6×5へ戻して生成される
  - **連続生成しても配慮が壊れない**（40回引き直して、離す2人が隣接しない・前列指定が前から2列目まで・後列指定が後ろから2列目まで・固定席が動かない・重複や取りこぼしがないことを確認済み）
  - エラー系はそれぞれ固有のメッセージになる（席不足／前列定員超過／固定席の重複／固定席が範囲外／名簿にない名前／書式ちがい／前後列の矛盾／探索失敗／名簿が空）
  - `#sk-out` はタブ区切りで、そのままExcelに貼れる
- **印刷**: `@media print` で座席表以外（ヘッダー・入力欄・説明・フッター）を隠す。**印刷ボタンはブラウザのダイアログを開く**ため、自動テストからは押さない
  - **名簿の流し込み**（2026-08-24にブラウザで確認済み）: 5列のCSV（出席番号・姓・名・性別・備考）から姓＋名を選んで12人を取り込み、
    「3年2組」で保存 →「この席をおぼえる」→ 再読込 →「よびだす」→ 10回引き直して**前回と同じ席0件・前回と同じ隣0件**。
    2×2に4人の原理的に不可能なケースでは、エラーにならず「同じ席にしない」だけ守って生成しメッセージが出る
- **手動確認観点**:
  - 「名簿はサーバーに送りません」の表示が消えていないか（このツールの前提そのもの）
  - 「消す」の確認ダイアログは `window.confirm`。**自動テストからは押さない**（ブラウザのモーダルで操作が止まる）
  - 印刷プレビューで座席表が1枚に収まるか（横の席数が多いクラスで確認）
  - 「離す」で斜めを許容していることが、FAQと実際の挙動で一致しているか
