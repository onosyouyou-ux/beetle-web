# ローマ字修行（`tools/romaji/`）

- **目的**: ローマ字には**ヘボン式（いま学校で習う）と訓令式（まえの教科書・親世代）の2つがある**ことを知らずに
  「自分の書き方はまちがい」と思ってしまうつまずきを消す。小3の2学期がねらい目
- **前提となる制度（2026-09-04更新）**: 2025-12-22の内閣告示で「ローマ字のつづり方」が約70年ぶりに改定され、
  **ヘボン式が基本**になった。同日に小学校学習指導要領解説（国語編・外国語活動／外国語編）も更新され、
  **2026年度（令和8年度）からの指導はヘボン式が基本**。訓令式は誤りではなく、定着した表記の変更は求められていない。
  **「学校＝訓令式」と書かない**（改定前の記述。2026-09-04に全面差し替え済み）
- **中心の仕掛け**: 「キーボードで うつ」で **ヘボン式・訓令式のどちらを打っても正解にする**。
  ここを片方だけ正解にすると、このアプリの主張と実装が食い違う（絶対に変えないこと）
- **アプリ画面に置くのは あそびかた3ステップだけ**（2026-08-26）。おうちのかたへ・よくある しつもんはランディング（`landing.html` の `#for-family` と `#faq`）に集約し、アプリからはヒーローの「おうちのかたへ・よくある しつもん」ボタンと紙面下部の `.nk-doc-ref` で行く。紙面のいちばん下に `.nk-back-tools`（`/edu-tools.html#kids` へ戻る）を置く
- **レイアウト型**: 教育系の静的アプリ（[_common.md](_common.md) 参照）。紙面 `.app-paper` 1180px ＋ モザイクタイル背景。
  SEOは `landing.html` に集約し、アプリ本体の canonical もランディングへ向ける
- **レスポンシブ**: [_common.md](_common.md) の「レスポンシブ共通ルール」に従う（幅は3段固定・タブレットは向きで出し分け）。
  **縦持ち・横持ちのどちらでも、ナビ＋ヒーロー＋盤面が1画面に収まる**こと（スクロールさせない）。ランディング側も同じ
- **画面のH1は「ローマ字しゅぎょう」（かな表記）**。`title`・OGPは検索向けに「ローマ字修行」
- **3モード（1セット10問）**:
  - `yomu`（ローマ字を よむ）: ローマ字を見せて ことば を4択。ヘボン式・訓令式を毎回ランダムに出し分け、
    こたえあわせでどちらの式だったかを表示する
  - `utsu`（キーボードで うつ）: ひらがなを見せて実際に入力。両式とも正解
  - `futatsu`（ふたつの 書き方）: `し` などを見せて、いま習う書き方（ヘボン式）／まえの書き方（訓令式）を2択
- **対応表（かな・ヘボン式・訓令式の3列。ヘボン式が先）は解説エリアに常設**（2026-08-27にメニュー内から移動）。ここが教材そのもの。表の中身は `romaji-data.js` から `romaji.js` が描く（HTMLに書き写さない）。表の下の一文で改定の日付（2025-12-22の内閣告示）に触れる
- **メニュー下の読み物は解説エリアに置く**（2026-08-27）。しゅぎょう中も見えるので、迷ったら下を見て確かめられる。枠の装飾（アプリの背景画像＋マスコット＋アクセント色の枠線）は `ninja-kids.css` に一元化。カタカナ・ローマ字・フォニックスで共通
- **しゅぎょうが3つのアプリは 768px 以上でメニューを横3分割**（2026-08-27）。縦3段だとそのぶん盤面が下へ押されるため。スマホは3段ルールどおり1カラム
- **成績は保存しない**（localStorage も使わない）

## データ（`js/romaji-data.js`）

`window.ROMAJI_DATA` が単一のデータ源。app 側はこの形しか知らない。

- `mora`: かな（拗音は2文字）→ ローマ字の配列。**先頭がヘボン式（いまの基本）**、2つ目以降が訓令式など
  （2026-09-04に順序を反転。`romaji.js` の `pickStyle()` も合わせて `kunrei` 側が2番目を取るようにしてある）
- `words`: `{ k: ひらがな, hint: その語で つまずく ところ }`。**hint を書けない語は入れない**
- `futatsu`: 2通りある かな（し・ち・つ・ふ・じ・しゃ・ちゃ・じゃ）と例。`hepburn` を先に書く
- `whyTwo`: 2つある理由の一文テンプレート（`{kunrei}` `{hepburn}` を差し替えて使う）

## 入力の受理ルール（`utsu`）

`romanizations()` が、かなをモーラに割ってから全ての組み合わせを作る。

1. **小さい「っ」**: 次のモーラの先頭字を重ねる（きって→kitte、ざっし→zasshi/zassi）
2. **「ん」**: ふつうは `n` / `nn`。ただし**次が母音・や行で始まるときは `nn` か `n'` のみ**（ほんや→honnya・hon'ya）。
   `honya` を受理すると「ほにゃ」と区別できなくなるため、あえて不正解にしている
3. **のばす音**: かなのとおり u・i を書く（がっこう→gakkou）。ヘボン式の長音記号（ō）は扱わない
4. 入力は小文字化・空白除去・全角アポストロフィの正規化をしてから照合する

- **手動確認観点**:
  - `utsu` でヘボン式・訓令式の両方が正解になるか（片方が落ちていないか）
  - 対応表・こたえあわせ・ヒントで **ヘボン式が「いま」、訓令式が「まえ」** の向きになっているか
  - `honya` のような n ひとつの入力が不正解になるか
  - こたえあわせに毎回ポイントの一文が出ているか
