# QA用語クイズ（`tools/qa-quiz/`）

- **目的**: QA・テストの用語を4択で確かめる静的ツール。`glossary`（読む）に対する「使う」側の入口で、参照系と操作系を対にする方針にそって作った
- **レイアウト型**: Reference系（[_common.md](_common.md) 参照）＋インタラクティブ部
- **構成**: `#tool`（クイズ本体）→ `#howto`（使い方3ステップ）→ `#about`（用語がわかると何が変わるか）→ `#faq`
- **出題データ**: `js/qa-quiz-data.js` の `QA_TERMS`（85語）。**出どころは `tools/glossary/index.html` の `.gl-card`**（`gl-term` / `gl-read` / `gl-cat` / `gl-def`）。辞典を直したらこちらも合わせて直す（単一の出どころは辞典側）
- **語数の内訳**: テストの基本28・バグ・起票まわり21・環境・リリース16・品質・進め方20 の計85語。カテゴリ（`c`）は 基本24／バグ21／品質12／リリース12／進め方6／環境4／技法4／開発2
- **モード**: `term2def`（用語 → 意味）と `def2term`（意味 → 用語）の2つ。範囲は「ぜんぶ」＋辞典の章4つ。**章は `QA_TERMS` の `s` から自動で組み立てる**ので、辞典に章が増えてもJSは触らなくていい
- **出題ルール**:
  - 1セット10問。範囲の語数が10未満ならその語数だけ出す
  - 誤答3つは**同じカテゴリ（`c`）の用語を優先**して選び、足りなければ他カテゴリで埋める。無関係な語が並ぶと消去法で解けてしまい練習にならないため（FAQに明記）
  - 選択肢の並びと出題順はどちらもシャッフルする
- **結果画面**: 正解数と正答率、まちがえた用語＋意味の一覧、用語辞典へのリンク。**成績は保存しない**（localStorage も使わない）
- **手動確認観点**:
  - 誤答の選択肢に正解と同義の語が混ざっていないか（同カテゴリ優先の副作用。とくに「基本」カテゴリは24語と多い）
  - `term2def` の選択肢は意味文が長いので1列、`def2term` は2列。狭い画面で1列に落ちるか
  - 辞典の語を増減したあと `QA_TERMS` を作り直したか（`.gl-card` からの抽出）
