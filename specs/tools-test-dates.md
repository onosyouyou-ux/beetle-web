# 意地悪な日付ジェネレーター（`tools/test-dates/`）

- **目的**: 日付まわりのテストで踏むべき境界の日付を、基準日から自動で並べてコピーできる静的ツール。`test-data` が入力欄を壊す文字を扱うのに対し、こちらは日付を扱う
- **レイアウト型**: Reference系（[_common.md](_common.md) 参照）＋インタラクティブ部
- **構成**: `#tool`（日付を出す）→ `#diff`（実装差分が出る計算）→ `#why`（なぜ日付で事故るのか）→ `#faq`
- **主要素**: `#dt-base`（基準日。初期値は今日）・`#dt-today`・`#dt-fy`（年度開始月。1/4/7/10、既定4月）・`#dt-format`（iso/slash/compact/ja/wareki/datetime/unix）・`#dt-list`（カード一覧）・`#dt-diff`・`#dt-out`（全件CSV）・`#dt-copyall`・`#dt-dl`・`.dt-copy-s`（カードごとのコピー。`data-v` が実際にコピーされる値）
- **カードの分類**: うるう年・2月／月末・月またぎ／年度・年またぎ／曜日・週／システムの境界／和暦・元号 の6グループ。危険度の高いものは `.is-warn`（オレンジ）で目立たせる
- **日付の持ち方**: すべてローカルの0時で保持する（日本にサマータイムがないため単純化できる）。Unixエポックと2038年問題だけは `fixedIso` を持ち、ISO 8601・Unix秒の表示ではそちらを優先する。1900-02-29 は実在しないため `literal` として文字列のまま扱い、表示形式の切り替えに追従しない
- **挙動（E2Eで検証）**:
  - 初期表示で今日を基準に36件の日付が並ぶ
  - 基準日を変えるとカードが再計算される（うるう年を基準にすると「基準年の2月末」が「基準年のうるう日」に変わる）
  - 表示形式を変えると全カードの値が追従する。和暦は「令和元年5月1日」「昭和64年1月7日」の形式（`Intl.DateTimeFormat` の和暦カレンダー）
  - `#dt-diff` の3枚は、基準年で必ず**答えが分かれる**組み合わせを出す（1月31日の1ヶ月後、うるう日の1年後、1ヶ月ずつ2回と2ヶ月まとめて）。同じ値が2つ並んだら例の選び方が壊れている
  - 「31日ある月の月末」「30日で終わる月の月末」は翌月以降から探すため、当月の月末カードと重複しない
- **手動確認観点**:
  - 和暦の元年表記（令和1年ではなく令和元年）が出ているか
  - 実在しない 1900-02-29 に「Excelが実在扱いする」という理由が添えられているか（誤った日付をただ配っている状態にしない）
  - ISO 8601（UTC）表示で日本時間の0時が前日の15:00Zになる。これは仕様どおりだが、タイムゾーンのずれを見せる意図であることが読み手に伝わるか
